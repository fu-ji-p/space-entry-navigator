# 実装時の判断記録

仕様書（docs/SPEC.md）から逸脱・補完した判断を列挙します。番号は記録順です。

## 1. 便益の基礎点に 0.75 の尺度を導入（仕様 5.3 からの逸脱）

仕様の式 `B = 100 × rel/3 × m × s × p` では、関連度 3 の便益が係数をかける前に 100 に達し、上限クリップで動機・希少性・トグルの効果がすべて消えます。初期値（目標 D3）では B2-6 と B3-1 が関連度 3 なので、受入基準「宇宙でしか実現できない価値をオンにすると B2-6 が上がる」を満たせません。

そのため `src/data/weights.ts` に `BENEFIT_BASE_SCALE = 0.75` を置き、関連度 3 の基礎点を 75 とし、係数で 100 まで伸びる余地を残しました。1.0 に戻せば仕様どおりの式になります。障壁の式は仕様どおりです（r=1 かつ段数差が大きいときのみクリップされます）。

## 2. 希少性係数の「障壁スコア W_w」はグループ内の最大値

`pairs.ts` の対応は障壁グループ（W1 = W1-1, W1-2 など）単位で定義されているため、`s_b = 1 + 0.3 × (W_w / 100)` の `W_w` にはグループ内の障壁スコアの最大値を用いました。「最も高い壁を越えたこと」が希少性を生むという解釈です。平均にしたい場合は `src/logic/score.ts` の `pairedBarrierScore` を変更してください。

## 3. 障壁スコアも 0〜100 にクリップ

仕様は便益のみ上限クリップを明記していますが、障壁も段数差で 100 を超え得るため同様にクリップしました。

## 4. 考察ルール `balanced` は fallback フラグで実装

「上記のいずれにも該当しない」を、`InsightRule` に `fallback?: boolean` を追加して表現しました。他のルールが 1 件も発火しないときだけ表示されます。

## 5. 診断の「未回答」は「いいえ」と同じ扱い

6 問すべてに答えなくても結果を出せるよう、未回答（null）は No と同じ扱いにし、画面には「未回答」の注記を出します。

## 6. ハッシュの形式と履歴の扱い

- 全画面で `#<route>?s=<state>` を使い、入力が初期値と同じなら `s` を省略します（初期状態の URL を短く保つため）。
- 探索画面の類型絞り込みは `d=<StageId>` で保持します。
- スライダー操作などの状態変化は `history.replaceState` でハッシュを置き換え、タブ移動は `pushState` で履歴に積みます。戻るボタンでスライダーの一手ずつが巻き戻ることを避けるためです。
- 診断の回答はメモリのみに保持します（仕様どおり）。

## 7. 型定義の置き場所

仕様の `src/data/types.ts` は「D 類型の定義」なので、TypeScript の型（`SimInput` など）は `src/data/schema.ts` に分けました。

## 8. 層の色と表示情報を `src/data/layers.ts` に集約

仕様 6 章の色の意味（企業=青、産業=緑、社会=橙、コスト=灰、技術=紫、意思決定=赤）をデータファイルとして置き、チャートとバッジが共通で参照します。

## 9. チャートのアクセシビリティ

Recharts の `Bar` にカスタム `shape` を渡し、棒ごとに `role="img"` と `aria-label`（項目名・キャッチコピー・スコア）を付けました。チャート直下には同内容の表を `sr-only` で置いています。棒のクリックで定義カード（`ItemDialog`）が開き、Esc キーで閉じます。

## 10. モバイルの入力パネル

`<details>` ではなく、`lg` 未満でだけ表示される開閉ボタン（`aria-expanded`）で入力パネルを折りたたみます。デスクトップでは常時表示で 2 カラムです。

## 11. 禁止語リストは空で同梱

`scripts/anon-words.txt` は著者が記入する前提のため、コメントのみで同梱しています。リストが空のときチェックは「判定なし」で成功します。`npm run build` の `prebuild` で `check:anon` と型チェックを実行します。

## 12. 便益カードの地域クラスター例

仕様 8 章に従い、B2-3 の例として地域の特色（射場・輸送、試験設備など）を残し、具体的な地名と企業名は書いていません。

## 13. 出典表記

`src/config/attribution.ts` の初期値は仕様どおり「本ツールは、異分野企業の宇宙産業参画に関する学術論文の分類枠組みに基づいています。」です。ホーム、フッター、レポートに表示します。

## 14. リポジトリとデプロイ

- 作業フォルダの親が別の git 管理下にあったため、本アプリは `space-entry-navigator/` に独立した git リポジトリとして作成しました。
- GitHub Pages は Actions ワークフロー（`.github/workflows/deploy.yml`）で公開する構成にし、`VITE_BASE` にリポジトリ名を自動で入れます。

## 15. バンドル分割

初回ロード 300KB（gzip）以下の目標に対し、React と Recharts を別チャンクに分けました（合計約 180KB gzip）。

## 16. 便益チャートの「動機に合致」の表現

動機を 1 つ以上選んだとき、合致する便益の棒を濃い枠線で強調し、それ以外を薄くします。動機未選択のときは全て同じ濃さです。

## 17. `generatedAt` の扱い

レポートの生成日時はレポート画面を開いた（または入力が変わった）時点の時刻で、ハッシュには含めません。

## 18. チャートのアニメーションは CSS transition で実装

Recharts 2.x の内蔵アニメーション（react-smooth）は、React 18 の StrictMode とカスタム `shape` の組み合わせで棒の幅が 0 のまま止まる現象が開発時に再現したため、`isAnimationActive={false}` にし、棒の `<rect>` に `transition: width 300ms` を付けてスコア変化時の遷移を表現しています。

## 19. ルート切替時のスクロール位置

タブ（ハッシュリンク）で画面を切り替えたとき、前の画面のスクロール位置が残らないよう、ルートが変わった場合のみ先頭へスクロールします。スライダー操作などで `s` だけが変わる場合はスクロールしません。

## 20. コミットの作者情報

匿名化の方針（コミットメッセージに個人名を含めない）に合わせ、初回コミットの作者名・メールはリポジトリ固有の中立な値にしています。公開リポジトリに push する前に、必要なら `git commit --amend --reset-author` で変更してください。

## 21. 画面・レポートは「低・中・高」の 3 段階だけを表示（仕様 3.3・3.5 からの逸脱）

論文は便益・障壁の関係を定性的に述べているだけで、数値的な度合いには触れていません。仕様の 0〜100 スコアはその定性的関係を順序として表すための仮置き（マトリクス、係数、基礎点の尺度）であり、2 桁の数字で見せると実際より精密に見えます。著者の判断で、画面・レポート・読み上げ・Markdown では数値を出さず、3 段階（低・中・高）だけを表示する方針にしました。

- 内部計算（`src/logic/score.ts`）と `SimScores` は 0〜100 のまま維持し、`src/data/bands.ts` の閾値（既定 34 / 67）で段階に丸めます（`src/logic/band.ts`）。既定ではマトリクスの関連度 1・2・3 がそのまま低・中・高になり、動機・希少性・トグルで一段動き得ます。
- （22 で記号表示に置き換え）ツールチップ、`aria-label`、定義カード、レポートの表も段階表示です。
- 考察ルールの条件（仕様 5.4 の「W3 が 60 以上」など）は段階で書き直しました: unknown-high = W3 が高、mission-driven = W3 が中以上、scarcity = W1-1 が高、tech-growth = W2-1 が中以上。
- 免責文とレポートに「段階は順序を示す目安で、数値的な根拠はありません」を追加しました。
- レポートの「上位 5 件」の並びは内部スコア順のままです（同じ段階内の順序は表示上の意味を持ちません）。

## 22. 棒グラフを ★/▲ の記号表示に置き換え、Recharts を外す（仕様 3.3・技術スタックからの逸脱）

3 段階にしても棒グラフは軸と長さで連続量を暗示するため、著者の判断で記号表示に変えました。便益は ★★☆、障壁は ▲▲△ のように 3 個の記号で段階を示し、必ず「低・中・高」の文字を併記します（色や記号だけに意味を持たせない）。障壁に ★ を使わないのは、★が「良い」の含みを持つためです。記号は `src/data/bands.ts` の `BAND_SYMBOLS` で変更できます。

- 一覧の各行はボタンで、クリック（Enter）で定義カードが開きます。`aria-label` に項目名・キャッチコピー・段階を含めます。
- 軸・目盛り・ツールチップ・`sr-only` の表は廃止しました（行の文字情報で同じ内容が読めます）。
- グラフがなくなったため Recharts を依存から外しました。仕様の技術スタックでは Recharts 固定でしたが、使用箇所がないためです。バンドルは約 180KB から約 69KB（gzip）になりました。
- W3 は赤い記号を破線枠で囲み、「性質が異なる」注記を続けています。
- レポートの Markdown でも `★★★ 高` のように記号と文字を併記します。

## 23. 重複表示とハードコード文言の整理

- 免責と出典は、本文に含む画面（ホーム、シミュレーター、レポート）ではフッターに繰り返さず、類型診断・探索ではフッターに表示します（免責は仕様どおりホームとレポートに常時表示）。
- 定義カードのダイアログは「閉じる」ボタンを右上の 1 つにし、カード本体と重複していた見出し（ID＋名称）は読み上げ専用にしました。
- モバイルの入力見出し「入力（D- → D3）」の矢印は仕様 6 章（矢印や「進む」を使わない）に反するため「入力（D- / D3）」にしました。
- コンポーネント側にハードコードされていた文言（スキップリンク、凡例、「3 つの軸」、「表 ⇔ 裏」、免責文の複製など）を `ja.ts` に移しました。
- 探索画面の「関連度（0〜3）が 2 以上」という数値注記は、数値を出さない方針に合わせて「関連の強い便益・障壁を強調」に変えました。
